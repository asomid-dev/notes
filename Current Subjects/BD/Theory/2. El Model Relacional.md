# 📂 Tema 2: El Model Relacional

---
## 1. 🎯 Objectius i Origen

> [!info] **Concepte Clau**
> El **model relacional** va ser proposat per **E.F. Codd (1969-1970)**. No va ser fins a la dècada dels **80** que van aparèixer els primers productes comercials amb un rendiment acceptable.

### Objectius Principals
* **Independència física**: Facilitar que la base de dades sigui percebuda com una estructura lògica independent de l'estructura física d'implementació de les dades.
* **Simplicitat i uniformitat**: Proporcionar una estructura lògica simple i uniforme basada únicament en un conjunt de relacions.
* **Atomicitat**: Tots els valors continguts a les relacions han de ser **atòmics** (no compostos).

---

## 2. 🧩 Estructura de Dades

### 2.1. Visió Informal vs. Formal
Informalment, una relació es pot visualitzar com una taula.

| Concepte Informal | Concepte Formal (Model Relacional) | Descripció |
| :--- | :--- | :--- |
| **Taula** | **Relació** | Estructura principal de dades. |
| **Fila** | **Tupla** | Col·lecció de valors de dades relacionats. |
| **Columna** | **Atribut** | Rol o paper que exerceix un domini en la relació. |

---

### 2.2. Components d'una Relació
Una relació es compon de dues parts principals:
1. **Esquema o Intenció (Capçalera)**: Defineix la part estructural $R(A_1, A_2, \dots, A_n)$. Inclou el nom de la relació i el conjunt d'atributs.
   * *Exemple*: `EMPLEATS(DNI, Nom, Sou)`.
1. **Extensió (Cos)**: Conjunt de tuples $t_i = \langle v_{i1}, v_{i2}, \dots, v_{in} \rangle$ contingudes en la relació en un moment determinat.

#### Dimensions de la Relació
* **Grau**: Nombre d'atributs que té l'esquema de la relació (nombre de columnes).
* **Cardinalitat**: Nombre de tuples que té l'extensió de la relació (nombre de files).

---

### 2.3. Atributs, Dominis i Valors Nuls

> [!note] **Atribut i Domini**
> * **Domini**: Conjunt de valors **atòmics**. Poden ser:
>   * **Predefinits**: ex. `INTEGER`, `VARCHAR`.
>   * **Definits per l'usuari**: ex. `Números_de_DNI`, `Noms`.
> * **Atribut**: Indica el rol específic que exerceix un domini dins d'un esquema.

#### Valors Nuls (`NULL`)
S'utilitzen quan el valor d'un atribut per a una tupla concreta és **desconegut** o **inaplicable**.

#### 💻 Exemple SQL: Creació de Taula, Atributs i Nuls
```sql
-- Definició de la relació EMPLEATS amb dominis i valors nuls
CREATE TABLE EMPLEATS (
    DNI VARCHAR(10) NOT NULL,          -- Atribut obligatori (no nul)
    Nom VARCHAR(50) NOT NULL,          -- Domini predefinit de cadena de caràcters
    Telèfon VARCHAR(15) NULL,          -- Pot prendre el valor NULL (desconegut/inaplicable)
    Sou NUMERIC(8, 2) CHECK (Sou > 0)  -- Domini numèric amb restricció de valor
);
````

---

### 2.4. ⚠️ Paranys de la Visió Tabular

La representació en forma de taula pot suggerir idees falses. En una relació formal:

1. Tots els valors dels atributs són **atòmics**.
2. **No hi ha tuples repetides**.
3. **No hi ha ordre** entre les tuples.
4. **No hi ha ordre** entre els atributs.

### 2.5. 🔑 Claus d'una Relació

```
            ┌────────────────────────────────────────┐
            │               Superclau                │
            └───────────────────┬────────────────────┘
                                │ (Mínima)
                                ▼
            ┌────────────────────────────────────────┐
            │            Clau Candidata              │
            └─────────┬────────────────────┬─────────┘
                      │                    │
          (Designada) │                    │ (No designada)
                      ▼                    ▼
            ┌──────────────────┐    ┌──────────────────┐
            │   Clau Primària  │    │ Clau Alternativa │
            └──────────────────┘    └──────────────────┘
```

- **Superclau**: Subconjunt d'atributs de l'esquema que identifica de manera única cada tupla.
- **Clau Candidata**: Superclau que no té cap subconjunt propi que sigui també superclau (és mínima).
- **Clau Primària (PK)**: La clau candidata designada per identificar les tuples. Per convenció, se **subratllen** els seus atributs.
- **Clau Alternativa**: Qualsevol clau candidata no designada com a primària.

#### 💻 Exemple SQL: Clau Primària, Alternativa (`UNIQUE`) i Composta

```
-- Donada la relació EMPLEAT(DNI, NSS, Nom, Telèfon, Sou)
CREATE TABLE EMPLEAT (
    DNI VARCHAR(10),
    NSS VARCHAR(12) NOT NULL,
    Nom VARCHAR(50) NOT NULL,
    Telèfon VARCHAR(15),
    Sou NUMERIC(8, 2),

    -- Clau Primària designada {DNI}
    CONSTRAINT PK_EMPLEAT PRIMARY KEY (DNI),

    -- Clau Alternativa {NSS} (garanteix la unicitat com a clau candidata)
    CONSTRAINT UQ_EMPLEAT_NSS UNIQUE (NSS)
);

-- Exemple de clau primària composta: DESPATX(Edifici, Número, Superfície)
CREATE TABLE DESPATX (
    Edifici VARCHAR(5),
    Número INT,
    Superfície NUMERIC(5, 2),

    CONSTRAINT PK_DESPATX PRIMARY KEY (Edifici, Número)
);
```

### 2.6. 🔗 Claus Foranes (Foreign Keys) i Connexions

- Subconjunt d'atributs d'una relació que **referencia la clau primària** d'una altra relació (o de la mateixa relació).
- Les connexions en el model relacional s'estableixen exclusivament mitjançant claus foranes perquè és un model **uniforme**.
- **Requisits d'una clau forana**:
    1. Tenir el mateix nombre d'atributs que la clau primària referenciada.
    2. Tenir dominis compatibles amb els de la clau primària referenciada.

#### 💻 Exemple SQL: Clau Forana Externa i Auto-referència

```
CREATE TABLE DEPARTAMENT (
    NomDep VARCHAR(30) PRIMARY KEY
);

CREATE TABLE EMPLEAT_ORGANIGRAMA (
    DNI VARCHAR(10) PRIMARY KEY,
    Nom VARCHAR(50) NOT NULL,
    EmpleatCap VARCHAR(10),  -- Auto-referència (cap directori)
    DepAssig VARCHAR(30),    -- Referència al departament

    -- Clau forana que referencia la mateixa taula EMPLEAT_ORGANIGRAMA
    CONSTRAINT FK_Cap FOREIGN KEY (EmpleatCap) REFERENCES EMPLEAT_ORGANIGRAMA(DNI),

    -- Clau forana que referencia la taula DEPARTAMENT
    CONSTRAINT FK_Dep FOREIGN KEY (DepAssig) REFERENCES DEPARTAMENT(NomDep)
);
```

## 3. ⚙️ Operacions del Model Relacional

Permeten manipular les dades emmagatzemades a la BD:

1. **Actualització**: Inserció, esborrat i modificació de tuples.
2. **Consulta**: Obtenció de dades deduïbles a partir de les relacions.

> [!tip] **Càlcul i Àlgebra Relacional** **SQL** és un llenguatge basat principalment en el **càlcul relacional**, tot i que incorpora també elements de l'**àlgebra relacional**.

#### 💻 Exemple SQL: Operacions DML (Inserció, Modificació, Esborrat i Consulta)

```
-- 1. Inserció de tuples (INSERT)
INSERT INTO DEPARTAMENT (NomDep) VALUES ('Producció'), ('Vendes');

INSERT INTO EMPLEATS (DNI, Nom, Telèfon, Sou)
VALUES ('40444255', 'Maria Domínguez', '937885146', 1500.00);

-- 2. Modificació de tuples (UPDATE)
UPDATE EMPLEATS
SET Sou = 1800.00
WHERE DNI = '40444255';

-- 3. Esborrat de tuples (DELETE)
DELETE FROM EMPLEATS
WHERE DNI = '40444255';

-- 4. Consulta de dades (SELECT)
SELECT Nom, Sou
FROM EMPLEATS
WHERE Sou >= 1500;
```

## 4. 🛡️ Regles d'Integritat i Polítiques Referencials

### 4.1. Regla d'Integritat d'Entitat

- S'aplica a les **claus primàries**.
- **Condicions**:
    1. Els atributs de la clau primària han de tenir valors únics en conjunt.
    2. Cap atribut de la clau primària pot prendre el valor nul (`NULL`).
- **Motivació**: Garantir la identificació unívoca de cada tupla.

---

### 4.2. Regla d'Integritat Referencial

- S'aplica a les **claus foranes**.
- **Condició**: Els valors d'una clau forana només poden ser valors existents de la clau primària referenciada o valors nuls (`NULL`).

#### Polítiques per al Manteniment de la Integritat Referencial

En intentar esborrar o modificar una clau primària referenciada, el sistema pot aplicar accions compensatòries:

> [!warning] **Polítiques davant d'Esborrat o Modificació**
> 
> 1. **Restricció (`RESTRICT` / `NO ACTION`)**: Prohibeix l'esborrat o modificació si hi ha referències jueves.
> 2. **Cascada (`CASCADE`)**: Propaga automàticament l'esborrat o modificació a les tuples que la referenciaven.
> 3. **Anul·lació (`SET NULL`)**: Assigna valors nuls (`NULL`) als atributs de la clau forana en les tuples referenciadores.

#### 💻 Exemple SQL: Configuració de Polítiques Referencials

```
-- 1. Política de RESTRICCIÓ (Restrict)
CREATE TABLE CLIENT (
    NumClient INT PRIMARY KEY,
    Nom VARCHAR(50)
);

CREATE TABLE COMANDA_RESTRICT (
    NumComanda INT PRIMARY KEY,
    NumClient INT,
    CONSTRAINT FK_Comanda_Client
        FOREIGN KEY (NumClient) REFERENCES CLIENT(NumClient)
        ON DELETE RESTRICT -- Impedeix esborrar el client si té comandes
        ON UPDATE RESTRICT
);

-- 2. Política de CASCADA (Cascade)
CREATE TABLE EDIFICI (
    NomEdif VARCHAR(10) PRIMARY KEY,
    Direcció VARCHAR(100)
);

CREATE TABLE DESPATX_CASCADE (
    Edifici VARCHAR(10),
    Número INT,
    Superfície NUMERIC(5, 2),
    PRIMARY KEY (Edifici, Número),
    CONSTRAINT FK_Despatx_Edifici
        FOREIGN KEY (Edifici) REFERENCES EDIFICI(NomEdif)
        ON DELETE CASCADE       -- Si s'esborra l'Edifici, s'esborren els seus despatxos
        ON UPDATE CASCADE       -- Si canvia el nom de l'Edifici, es canvia en el despatx
);

-- 3. Política d'ANUL·LACIÓ (Set Null)
CREATE TABLE VENEDOR (
    NumVenedor INT PRIMARY KEY,
    Nom VARCHAR(50)
);

CREATE TABLE CLIENT_SETNULL (
    NumClient INT PRIMARY KEY,
    Nom VARCHAR(50),
    NumVenedor INT,
    CONSTRAINT FK_Client_Venedor
        FOREIGN KEY (NumVenedor) REFERENCES VENEDOR(NumVenedor)
        ON DELETE SET NULL      -- Si s'esborra el venedor, el camp passa a ser NULL
        ON UPDATE SET NULL
);
```

---
### 4.3. Regla d'Integritat de Domini

- Els valors d'un atribut han de pertànyer strictly al seu domini.
- Només es permeten comparacions entre dominis compatibles.
- **Suport en SQL**: Principalment per als dominis predefinits i clàusules de verificació (`CHECK`).

#### 💻 Exemple SQL: Restricció de Domini amb `CHECK`

```
CREATE TABLE EMPLEAT_DOMINI (
    DNI VARCHAR(10) PRIMARY KEY,
    Sou NUMERIC(8,2),
    Edat INT,
    -- Valors dins del domini admès
    CONSTRAINT CHK_Sou_Positiu CHECK (Sou > 0),
    CONSTRAINT CHK_Edat_Laboral CHECK (Edat BETWEEN 18 AND 65)
);
```
