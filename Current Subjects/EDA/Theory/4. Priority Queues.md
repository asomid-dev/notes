## 1. Abstract Data Type: Priority Queue

### Motivation

Standard FIFO queues process elements strictly in their order of arrival. However, many computing applications require processing elements according to their **priority or urgency**:

- **Task scheduling** in operating systems (shorter or higher-priority tasks run first).
- **Simulation systems** (discrete events must be simulated in chronological order).
- **Greedy algorithms** (at each step, the locally best choice must be retrieved, e.g., Dijkstra's algorithm or Prim's MST).

### Supported Operations

A priority queue supports two fundamental operations:

1. **add(x)**: Inserts element `x` into the queue.
2. **remove_min()**: Removes and returns an element with the minimum key/priority (or `remove_max()` for maximum priority queues).

### Implementation Comparison

| Implementation                         | `add`            | `remove_min`     | Notes                                                                            |
| -------------------------------------- | ---------------- | ---------------- | -------------------------------------------------------------------------------- |
| **Unordered sequential (vector/list)** | $\Theta(1)$      | $\Theta(n)$      | Fast insertion at the end; linear scan to find minimum.                          |
| **Ordered sequential (increasing)**    | $\Theta(n)$      | $\Theta(n)$      | Insertion takes linear time; removing from the front is linear in plain vectors. |
| **Ordered sequential (decreasing)**    | $\Theta(n)$      | $\Theta(1)$      | Minimum is at the back (`pop_back()` is $\Theta(1)$).                            |
| **Ordered circular vector**            | $\Theta(n)$      | $\Theta(1)$      | Constant removal from front, but linear insertion.                               |
| **Binary Heap**                        | $\Theta(\log n)$ | $\Theta(\log n)$ | **Optimal balance** between insertion and removal.                               |

## 2. Structural Foundations: Complete Binary Trees

### Definitions & Terminology

- **Level of a node**: The distance (number of edges) from the root to that node. The root is at level $0$.
- **Height of a tree (**$h$**)**: The maximum level among all its nodes.
- **Perfect Binary Tree**: A binary tree where all leaves are at the exact same level $h$. $$\text{Total nodes in a perfect tree of height } h = \sum_{i=0}^h 2^i = 2^{h+1} - 1$$
- **Complete Binary Tree**: A binary tree of height $h$ where:
    1. The first $h - 1$ levels are completely full.
    2. The leaves at level $h$ are packed **as far to the left as possible**.

### Node Bounds and Height Proof

- **Number of nodes (**$n$**)**:
    - Minimum nodes: Levels $0$ through $h-1$ are full, plus a single leaf at level $h$: $$n_{\min} = (2^h - 1) + 1 = 2^h$$
    - Maximum nodes: A perfect binary tree of height $h$: $$n_{\max} = 2^{h+1} - 1$$
    - Therefore, for any complete binary tree: $$2^h \le n \le 2^{h+1} - 1 < 2^{h+1}$$
- **Guaranteed Height**: Taking base-2 logarithms yields $h \le \log_2 n < h + 1$, meaning: $$h = \lfloor \log_2 n \rfloor \in \Theta(\log n)$$ Because the height is strictly bounded by $\Theta(\log n)$, all operations traversing the root-to-leaf path run in logarithmic time.

## 3. The Binary Heap Data Structure

### Heap Order Property

A **heap** is a complete binary tree that satisfies the ordering property:

- **Min-Heap**: The key of every node is $\le$ **the keys of its children**. The root contains the absolute minimum element.
- **Max-Heap**: The key of every node is $\ge$ **the keys of its children**. The root contains the absolute maximum element.

_(Note: Unless specified otherwise, "heap" refers to a min-heap.)_

### Implicit Vector Representation (No Pointers!)

Because complete binary trees have no "holes" in their levels, they are stored compactly inside a flat **std::vector** without storing left/right child pointers:

- **Index 0 is left unused** (or reserved).
- **Root** is located at index **1**.
- For any node at index **i**:
    - **Parent index**: $\lfloor i / 2 \rfloor$
    - **Left child index**: $2i$
    - **Right child index**: $2i + 1$

```cpp
Tree:              (2)              Vector indices:    1   2   3   4   5   6
                  /   \             Vector values:   [-]  2   7   4  10   8   9
                (7)   (4)
               /  \   /
            (10) (8) (9)
```

## 4. Core Algorithms

A. Insertion: `add(x)` & `move_up`

1. Append `x` at the first available position in the vector (`t.push_back(x)`). This preserves the complete binary tree structure.
2. Restore the heap-order property by calling **move_up** (percolate up / bubble up): compare `x` with its parent at $\lfloor i/2 \rfloor$; if $t[i/2] > t[i]$, swap them and continue upwards until the root or a smaller parent is reached.

### C++ Recursive Implementation:
```cpp
void move_up(int i) {
    if (i != 1 and t[i / 2] > t[i]) {
        swap(t[i], t[i / 2]);
        move_up(i / 2);
    }
} // Cost: Θ(log n)

void add(Elem& x) {
    t.push_back(x);
    move_up(size());
} // Cost: Θ(log n)
```

### Iterative Optimisation (Avoiding repeated swaps):

Instead of swapping at every level, shift parents down and insert `x` directly into its final resting slot:

```cpp
void add(Elem& x) {
    t.push_back(x);
    int i = size();
    while (i != 1 and t[i / 2] > x) {
        t[i] = t[i / 2];
        i = i / 2;
    }
    t[i] = x;
} // Cost: Θ(log n)
```

## B. Extraction: `remove_min()` & `move_down`

1. Save the root element `t[1]` (which is the minimum).
2. Move the **last element** of the vector to the root position (`t[1] = t.back()`) and remove the last position (`t.pop_back()`).
3. Restore the heap-order property by calling **move_down** (percolate down / sink): compare the node with its children; if it is greater than the **smaller child**, swap with that smaller child and continue sinking down.

### C++ Recursive Implementation:
```cpp
void move_down(int i) {
    int n = size();
    int c = 2 * i; // Left child
    if (c <= n) {
        if (c + 1 <= n and t[c + 1] < t[c]) c++; // c is the smallest child
        if (t[i] > t[c]) {
            swap(t[i], t[c]);
            move_down(c);
        }
    }
} // Cost: Θ(log n)

Elem remove_min() {
    if (empty()) throw ErrorPrec("Empty PrioQueue");
    Elem x = t[1];
    t[1] = t.back();
    t.pop_back();
    move_down(1);
    return x;
} // Cost: Θ(log n)
```

## 5. Heap Construction (Building a Heap)

There are two primary ways to convert an arbitrary array of $n$ elements into a valid heap:

### 1. Top-Down Construction

- Start with an empty heap and perform $n$ **successive** **add** **calls**.
- **Cost Analysis**: Each insertion takes $O(\log n)$. For $n$ elements: $$T(n) = \sum_{k=1}^n \Theta(\log k) = \Theta(n \log n)$$
### 2. Bottom-Up Construction (Linear Time $\Theta(n)$)

- **Algorithm**:
    1. Copy all $n$ elements directly into the vector in arbitrary order.
    2. Starting from the last internal node (level $h-1$, index $i = \lfloor n/2 \rfloor$) down to the root ($i = 1$), call `move_down(i)`. _(Leaves at level_ $h$ _are already trivial 1-element heaps, so they do not need to sink.)_

### Mathematical Proof of $\Theta(n)$ Cost:

In a perfect binary tree of height $h$ with $n = 2^{h+1} - 1$ nodes:

- Level $i$ contains $2^i$ nodes.
- A node at level $i$ can sink at most down to level $h$, requiring at most $(h - i)$ comparisons/swaps.

Total number of swaps $S$ is bounded by: $$S = \sum_{i=0}^{h-1} 2^i (h - i)$$
Let $k = h - i$: $$S = \sum_{k=1}^h k \cdot 2^{h-k} = 2^h \sum_{k=1}^h \frac{k}{2^k}$$

Using the standard series identity $\sum_{k=1}^{\infty} \frac{k}{2^k} = 2$: $$S = 2^{h+1} - h - 2 < 2^{h+1} - 1 = n$$
Because the majority of nodes are at or near the bottom (where their remaining height is small), the total work is strictly linear: $$\mathbf{T(n) \in \Theta(n)}$$

## 6. Heapsort

Invented by J. W. J. Williams in 1964, Heapsort sorts $n$ elements in optimal comparison time:

1. **Build a heap** from the $n$ elements:
    - Bottom-up build takes $\Theta(n)$ time.
2. **Extract elements**: Call `remove_min()` (or `remove_max()`) $n$ times:
    - $n \times \Theta(\log n) = \Theta(n \log n)$.
3. **Total Time**: $\Theta(n) + \Theta(n \log n) = \mathbf{\Theta(n \log n)}$.

### In-Place Single-Vector Heapsort

To avoid using extra memory ($O(1)$ auxiliary space):

- Divide the single vector into two partitions: a **heap partition** on the left and a **sorted partition** on the right.
- To sort in **increasing order**, use a **Max-Heap**:
    1. Build a max-heap in-place.
    2. Swap the root (maximum) with the last element of the heap partition.
    3. Shrink the heap size by 1 and call `move_down(1)` on the remaining heap.
    4. Repeat until the heap is empty; the array is now sorted in increasing order.

## 7. The Selection Problem ($k$-th Smallest Element)

Given an unsorted list $S$ of $n$ numbers and an integer $k$, find the $k$-th smallest element:

1. **Build a min-heap** using the bottom-up method: $\Theta(n)$.
2. **Call** **remove_min()** $k$ **times**: $\Theta(k \log n)$.
3. The $k$-th extracted element is the answer.

$$\text{Total Cost} = \mathbf{\Theta(n + k \log n)}$$

- If $k$ is small ($k = O(n / \log n)$): Total cost is $\Theta(n)$ **linear time**!
- If finding the median ($k = n/2$): Total cost is $\Theta(n \log n)$.
